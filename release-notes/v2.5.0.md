### Your settings now survive updates
• **Extra flags field** in Server Settings — type any additional llama-server flags (for example `-np 1`); they are appended last and kept across updates. An unknown flag stops the server, so check View Server Logs… if it doesn't start.
• **`~/.config/llama/server.local.conf`** — where those flags live: a file for your own settings that LlamaMate creates once and never overwrites. You can also edit it directly (`EXTRA_ARGS="…"`, or llama.cpp's `export LLAMA_ARG_…=` variables); the Settings field only changes the `EXTRA_ARGS` line.
• **Unknown keys in `server.conf` are kept** when the app or the installer rewrites it (they used to be dropped).
• **Hand-edited start script is backed up**, not silently replaced: it is saved as `llama-server-start.sh.user-<date>` and the app tells you where. Unmodified copies from earlier versions are still updated quietly.

### Faster by default
• **Threads**: with Threads = 0 (auto) LlamaMate no longer passes `-t 0`, which made llama.cpp use *all* cores including efficiency cores. llama.cpp now picks the performance cores itself.
• **Apply & Restart only restarts when something changed**, so llama-server keeps its prompt cache — no minute-long wait on the next message from a coding agent after pressing Apply with nothing changed.

### Speed settings
• **MTP (multi-token prediction)** — Server Settings → MTP. LlamaMate reads the model's GGUF header and, when the model ships MTP heads, turns on `--spec-type draft-mtp` (draft tokens: 4, adjustable 2–6). On models that support it this is often about twice as fast at generating text; drafts are checked by the main model, so answers are the same. Shown as "✓ model has MTP" in Settings; can be turned off. Needs a recent llama.cpp.
• **Parallel requests** — Server Settings → Parallel: Auto (llama.cpp default), 1, 2 or 4. "1" suits a single user with one app; more if several apps or people use the server at once. For 2+ the slots share one KV cache, so each still gets the full context.

### More accurate RAM estimate
• Hybrid models (for example Qwen3.5 / Qwen3-Next with Gated DeltaNet layers, or models with per-layer KV heads) only keep a KV cache on their attention layers. The estimate now counts just those layers instead of all of them — for such models it was several times too high. Sliding-window models are marked "(approx.)".

**Upgrade:** `brew update && brew upgrade --cask llamamate`
